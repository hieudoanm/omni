# macOS — Architecture

Module boundaries, request lifecycle, and tenancy for Omni.

## Directory Structure

Code is organized by tab, with an `OmniCore` target holding everything unit-testable (models + protocol-driven services) and the `Omni` target holding system-facing services, ViewModels, and SwiftUI views.

```text
Omni.xcodeproj/           Xcode project (generated by xcodegen from project.yml)
├── Omni/                     App target
│   ├── App/                  ViewModels (one per tab)
│   │   ├── Battery/          BatteryViewModel
│   │   ├── Clipboard/        ClipboardViewModel
│   │   ├── Clock/            Clock/Pomodoro/Stopwatch/Timer/WorldClock ViewModels
│   │   ├── Front/            AppsViewModel
│   │   ├── Homebrew/         HomebrewViewModel
│   │   ├── IP/               IPViewModel
│   │   ├── Memory/           MemoryViewModel
│   │   ├── Network/          NetworkViewModel
│   │   ├── Ports/            PortsViewModel
│   │   ├── Workspaces/       WorkspacesViewModel
│   │   └── Shared/           AppViewModels, DashboardRouter, LaunchAtLogin,
│   │                         MacOSXApp (@main), MenuBarIcon, WindowPresenter, …
│   ├── Services/             System-facing services (Omni target)
│   │   ├── Battery/    BatteryMonitor
│   │   ├── Clipboard/  ClipboardMonitor, PasteboardManager
│   │   ├── IP/         IPLookupService
│   │   ├── Memory/     MemoryMonitor, DiskMonitor, SwapMonitor, CPUMonitor,
│   │   │               SystemInfoMonitor, MemoryPressureMonitor
│   │   ├── Network/    NetworkMonitor, IOKitNetworkInterfaceClassifier
│   │   ├── Workspaces/ AccessibilityManager, CoreGraphicsWindowLister,
│   │   │               ScreenManager, ApplicationLauncher, WindowArranger,
│   │   │               WorkspaceCaptureService, WorkspaceRestoreService
│   │   └── Shared/     MonitorError
│   ├── Views/
│   │   ├── Apps/ Battery/ Clipboard/ Clock/ Front/ Homebrew/ IP/ Memory/
│   │   ├── Network/ Ports/ Workspaces/ — one view folder per feature
│   │   └── Shared/     DesignSystem (Spacing, Radius, Palette, Typography,
│   │                   Motion, SurfaceMetrics), MenuBarView, DashboardView,
│   │                   SettingsView, SurfaceLayout, …
│   ├── Resources/            Assets.xcassets (AppIcon)
│   ├── Info.plist            LSUIElement menu-bar agent
│   └── Omni.entitlements     app-sandbox off
├── OmniCore/                 Framework target (public, unit-tested)
│   ├── Models/               Battery, Clipboard, Clock, Front, Homebrew, IP,
│   │                         Memory, Network, Ports, Shared, Workspaces
│   ├── Services/             Applications, Battery, Clock, Front, Homebrew,
│   │                         IP, Network, Ports, Workspaces
│   ├── BrewSettingsStore.swift, ByteFormatter.swift, ClockFormatter.swift,
│   ├── FileManager+AppSupport.swift, SettingsStore.swift
├── OmniTests/                Unit-test bundle (@testable import OmniCore)
```

Tests mirror the `OmniCore` layout under `OmniTests/Core/…`, one suite per feature, so parsing, math, and store logic are verified independently of SwiftUI.

## Layering rules

- Views never query Mach or filesystem APIs directly — they go through ViewModels → Services → Core.
- All calculations live in `Core` so they are unit-testable.
- Monitoring logic returns `Result<T, MonitorError>` — never panics.
- Discovery and termination are protocol-based (`PortDiscovering`, `ProcessTerminating`, `WorkspaceCapturing`, `WorkspaceRestoring`, `WindowListing`, `IPLookupServicing`, `RunningAppProviding`) so unit tests can substitute mocks.
- Views never touch `NSPasteboard` directly — go through `PasteboardManager`.
- Views never touch window APIs directly — go through `WorkspaceCapturing`, `WorkspaceRestoring`, `WindowListing`.
- Views never build HTTP requests directly — go through `IPLookupServicing`.
- Views never touch IOKit directly — go through `BatteryMonitor`.
